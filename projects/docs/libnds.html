Practical Guide to video.h (libnds)

The Nintendo DS graphics processor features two rendering units (called Engines):

  • Main Engine (Engine A): Supports 2D graphics and the 3D engine.
  • Sub Engine (Engine B): Supports 2D graphics only.

1. Video Mode Configuration

videoSetMode(uint32 mode)

What it does: Configures the display mode and enables/disables layers (backgrounds and sprites) on the Main Engine (Engine A / Main Screen).

How to use: Called during game initialization to define how the main screen will operate (whether using simple 2D graphics, 3D, or direct framebuffer) and which elements will be visible.

Parameters:

  • mode (uint32): A bitmask. You combine different constants using the bitwise OR operator (|).
    • Display Modes (Choose 1):
      • MODE_0_2D to MODE_5_2D: Defines the background (BG) mode. MODE_0_2D allows 4 text backgrounds; MODE_5_2D allows advanced rotation/scaling.
      • MODE_FB0 to MODE_FB3: Direct Framebuffer mode (writes pixels directly to VRAM).
      • MODE_FIFO: Enables the 3D engine display.
    • Layer Activation (Combine as needed):
      • DISPLAY_BG0_ACTIVE, DISPLAY_BG1_ACTIVE, DISPLAY_BG2_ACTIVE, DISPLAY_BG3_ACTIVE: Activate the respective background layers.
      • DISPLAY_SPRITE_ACTIVE: Enables sprite rendering (2D characters/objects).
      • DISPLAY_SPRITE_1D: Sets sprite memory to be organized linearly in 1D (easier to program).

Example usage:

// Configures Mode 0 2D on the main screen and enables Background 0 and Sprites
videoSetMode(MODE_0_2D | DISPLAY_BG0_ACTIVE | DISPLAY_SPRITE_ACTIVE | DISPLAY_SPRITE_1D);

videoSetModeSub(uint32 mode)

What it does: Configures the display mode and enables layers on the Secondary Engine (Sub / Screen B).

How to use: Works exactly like videoSetMode, but affects only the sub screen.

Parameters:

  • mode (uint32): Combination of constants identical to videoSetMode.
Note: The Sub Engine does not support 3D modes or direct framebuffers. Use only 2D modes (MODE_0_2D to MODE_5_2D).

Example usage:

// Configures the secondary screen for Mode 0 2D with only Background 0 active
videoSetModeSub(MODE_0_2D | DISPLAY_BG0_ACTIVE);

2. VRAM Memory Management

The Nintendo DS has several VRAM memory banks (A, B, C, D, E, F, G, H, I). For the video hardware to render anything, you need to "map" (assign) these memory banks to a specific function.

vramSetBankA(VRAM_A_TYPE mode)

(There are equivalent functions for the other banks: vramSetBankB, vramSetBankC, etc.)

What it does: Assigns VRAM Bank A (128 KB) to a specific graphics purpose (Backgrounds, Sprites, 3D Textures, etc.).

How to use: Must be called before attempting to load any image or palette into memory.

Parameters:

  • mode (VRAM_A_TYPE): An enum value specifying the destination of the memory bank.
    • VRAM_A_MAIN_BG: Allocates this bank for Main Engine Backgrounds.
    • VRAM_A_MAIN_SPRITE: Allocates this bank to store Main Engine Sprite images.
    • VRAM_A_TEXTURE: Allocates this bank to store 3D engine textures.
    • VRAM_A_SUB_BG: Allocates this bank for Sub Engine Backgrounds.
    • VRAM_A_LCD: Disconnects the bank from the graphics engine, allowing direct CPU read/write access.

Example usage:

// Allocates Bank A for main screen backgrounds
vramSetBankA(VRAM_A_MAIN_BG);

// Allocates Bank B for main screen sprites
vramSetBankB(VRAM_B_MAIN_SPRITE);

// Allocates Bank C for secondary screen backgrounds
vramSetBankC(VRAM_C_SUB_BG);

3. Physical Screen Control and Swapping

By default, the Main Engine renders on the TOP screen, and the Sub Engine renders on the BOTTOM (Touch) screen.

lcdMainOnBottom()

What it does: Inverts the physical display. Maps the Main Engine (A) to the bottom screen (Touch) and the Sub Engine (B) to the top screen.

How to use: Simple call without arguments whenever you want to run 3D or advanced graphics on the touch screen.

Parameters: None.

lcdMainOnTop()

What it does: Restores the default behavior (Main Engine on top, Sub Engine on bottom).

Parameters: None.

Example usage:

lcdMainOnBottom(); // Engine A now renders on the bottom screen

4. Dynamic Layer Activation and Deactivation

Instead of reconfiguring the entire video mode with videoSetMode, you can turn individual layers on and off at runtime.

videoBgEnable(uint32 flags) / videoBgEnableSub(uint32 flags)

What it does: Enables one or more background layers that were hidden.

flags parameter (uint32): The layers to enable combined with |.

Options: DISPLAY_BG0_ACTIVE, DISPLAY_BG1_ACTIVE, DISPLAY_BG2_ACTIVE, DISPLAY_BG3_ACTIVE.

videoBgDisable(uint32 flags) / videoBgDisableSub(uint32 flags)

What it does: Hides/disables specific background layers.

flags parameter (uint32): The layers to disable combined with |.

Example usage:

// Temporarily hides background 0 on the main screen (e.g., to pause the game)
videoBgDisable(DISPLAY_BG0_ACTIVE);

// Re-enables background 0
videoBgEnable(DISPLAY_BG0_ACTIVE);

Complete C Initialization Example

Below is functional C code demonstrating how to bring these basic commands together to prepare the Nintendo DS to render graphics:

#include <nds.h>

void inicializarVideo(void) {
    // 1. Map VRAM memory banks
    vramSetBankA(VRAM_A_MAIN_BG);     // Bank A -> Main screen Backgrounds
    vramSetBankB(VRAM_B_MAIN_SPRITE); // Bank B -> Main screen Sprites
    vramSetBankC(VRAM_C_SUB_BG);      // Bank C -> Sub screen Backgrounds

    // 2. Configure Main Screen video mode
    // Uses Mode 0 2D, enables BG0, and enables Sprites in 1D mode
    videoSetMode(MODE_0_2D | DISPLAY_BG0_ACTIVE | DISPLAY_SPRITE_ACTIVE | DISPLAY_SPRITE_1D);

    // 3. Configure Sub Screen video mode
    // Uses Mode 0 2D and enables BG0
    videoSetModeSub(MODE_0_2D | DISPLAY_BG0_ACTIVE);

    // 4. Optional: Assign the Main Engine to the bottom screen
    lcdMainOnBottom();
}

int main(void) {
    inicializarVideo();

    while(1) {
        swiWaitForVBlank(); // Waits for vertical screen synchronization
    }

    return 0;
}
